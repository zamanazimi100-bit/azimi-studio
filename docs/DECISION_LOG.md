# AZIMI DECISION LOG

## Purpose

This file records important decisions made during AZIMI development.

It helps preserve project direction, reasoning and continuity.

---

## 2026-09-19 — GitHub as the Source of Truth

### Decision

GitHub will be the primary source of truth for AZIMI project files, documentation, code and development history.

### Reason

Project context must remain organized and recoverable across sessions.

### Impact

Important plans, decisions, current status and changes must be documented in the repository.

---

## 2026-09-19 — No Unverified Completion Claims

### Decision

A feature must not be declared complete without implementation, testing, verification and documentation.

### Reason

Accuracy and trust are more important than claiming progress too early.

### Impact

Unverified features must be clearly marked as NOT YET VERIFIED.

---

## 2026-09-19 — Phone-First Development

### Decision

AZIMI development must remain practical from an Android phone whenever possible.

### Reason

The current development environment is phone-first.

### Impact

Instructions, tools and workflows should support mobile development.

---

## 2026-09-19 — Defensive Security

### Decision

AZIMI security features must focus on protection, privacy, recovery and defensive use.

### Reason

The project should protect the user, data and devices without creating harmful functionality.

### Impact

Security features must follow privacy-first and defensive principles.

---

## 2026-09-19 — Secret Separation

### Decision

Passwords, verification codes, recovery codes, API keys and other private credentials must never be stored in public project documentation.

### Reason

Sensitive information must remain protected.

### Impact

Documentation may describe security rules but must not contain real secrets.

---

## 2026-09-19 — Current Build Order

### Decision

Complete Z Vault authentication testing before beginning real RAM and memory diagnostics.

### Reason

The current phase focuses on stabilizing and verifying the Guardian foundation.

### Impact

The next exact task is Vault authentication verification.

---

## Decision Rule

Every major AZIMI decision should include:

1. The date.
2. The decision.
3. The reason.
4. The impact on the project.

Decisions may be updated when new verified information becomes available.
